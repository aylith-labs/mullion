Personal fork of microsoft/terminal

Windows Terminal, with more in it.

Mullion is a fork of Microsoft's Windows Terminal that evolves on its own terms. Script it from outside the process, get back what your panes were running after a restart, and have links, previews and windows behave the way you'd expect.

Highlights

The parts worth switching for

Automation

Drive it from outside the process

Every window opens a local pipe another program can talk to: ask what tabs and panes exist, read back exactly what one of them printed, or type into a specific pane. No simulated keystrokes, no guessing which window is focused. Microsoft looked at this exact idea twice and passed on it; their own automation surface can't reach a pane running inside WSL.

How the control pipe works
Session restore

Bring back what was actually running

Reopening the terminal puts back the programs the panes were running, not just the shells. A coding agent returns to the same conversation; tmux, screen, zellij, herdr and shefrd reattach to the session their server is still holding. Panes that resume nothing repaint their saved scrollback, so a crash costs you the process, not the history.

Links

Links that behave like you'd expect

Click a link without holding Ctrl, even inside tmux. Hover it and a card says what a click will do and where it really goes, with Open, Copy and Show in Explorer buttons, landing wherever there's room instead of running off the window's edge. A WSL file link opens the real file, not an error.

Links that do something

  • Paths are links: Windows, UNC and POSIX paths, resolved in the right WSL distribution.
  • Click without Ctrl, even inside tmux and other mouse-mode apps.
  • A link card with actions, Markdown, and file previews.
  • Integrations for GitHub, Jira and Slack, plus your own regex rules.

Tabs, windows and panes

  • Tab strip on any edge, with tab numbers and per-window overrides.
  • Each window reopens where it was, or docks to a screen edge.
  • Pane title bars with draggable dividers.
  • Light and dark colour schemes in pairs that follow the OS.
UI & theming features

    How it's run

    A fork on its own terms

    Relationship to upstream

    Features land here because they belong in this terminal, whether or not microsoft/terminal would ever take them. Upstream is merged in, never rebased onto, for its bug and security fixes, and its issues and pull requests are read before anything here is built.

    Nothing goes back: conflicts resolve in favour of this fork's behaviour, and the divergence is the point. The name is the upright bar between window panes.

    Two slots, one machine

    SlotWhat it is
    Dev muldThe one you live in. It changes only when you press promote inside it.
    Test multDisposable. Refreshed on demand to verify a build in a window of its own.

    Every push to main builds, tests and packages both in CI; a background poller stages the newest build.

    Mullion for Windows

    Download the portable x64 build, extract the entire ZIP into a writable folder, and open mullion.exe. Keep the included .portable file: settings stay in that folder.
